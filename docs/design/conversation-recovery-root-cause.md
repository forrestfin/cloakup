# 会话交互故障：基于证据的复审与验收

## 预期行为与必要约束

执行器应依次完成：准备当前文档的隔离读取通道 → 读取会话列表 → 打开指定会话 → 核对候选人与岗位 → 读取真实消息与唯一编辑器 → 才允许业务决策。

浏览器窗口存在、页面可截图、DOM 可读取、会话身份可核验是四种不同的证据，不能互相替代。
任务暂停时不自动推进业务；显式诊断只能选中已有的本地绑定会话，不暴露输入、发送、申请简历或交换联系方式能力。
发现草稿、登录要求或平台校验时不选中会话，不覆盖内容。恢复需有真实核验证据；没有证据不能清除待办。

## 实际现象与证据

1. 执行桌面显示 BOSS 已登录，25 条会话存在，右侧最初未选中联系人。
2. 原失败会话有本地候选人和岗位绑定，列表中确实存在；不是从名称猜测一个新候选人。
3. 浏览器 CDP 与帧树可响应；主页面读取成功。
4. CloakBrowser 隔离通道曾超过 6 秒仍未返回。重建隔离上下文后恢复。
5. 上一版恢复保护检查耗时约 11.5 秒，随后同一隔离通道读取约 10 毫秒。仅放宽同一个 DOM 超时并不能清楚表达初始化与执行的差异。
6. 通过正常 CloakBrowser 点击打开原目标后，实际身份、消息列表与唯一编辑器核验通过，分别完成约 2.7 秒、3.5 秒的受限诊断。未发送消息。
7. 更早记录里还有点击超时、目标未核实等不同阶段。部分异常曾被重写为笼统的 `target_unverified`，因此不能倒推所有历史故障都是同一个原因。

原始与验收产物：`runs/verification/browser-channel-baseline.json`、`browser-channel-diagnostics.json`、`original-target-probe.json`、`first-principles-acceptance.json`。

## 可验证假设

| 假设 | 如何验证 | 当前结论 |
| --- | --- | --- |
| 浏览器整体失去响应 | 比较 CDP、帧树、主页面读取与隔离读取 | 这次不支持：前三项可响应 |
| 登录失效是唯一原因 | 检查实际登录/平台验证标记及登录后的会话行为 | 不支持：登录完成后曾继续出现读取故障 |
| SDK 初始化或隔离上下文恢复，被统一 5 秒限制误判 | 对照 SDK `_ready/_install` 调用链、初始化与后续读取耗时 | 支持；精确到 SDK 内哪一条初始化命令变慢尚未证明，不宣称唯一内部原因 |
| 原目标已消失或本地身份绑定错误 | 查目标行，并实际打开后核验头部、消息、编辑器 | 本次不支持：原目标实机核验通过 |
| 遮挡、移动或点击异常导致选不中 | 用相同原生选择适配器验证，保留失败阶段 | 本次两次成功；不能据此否认历史点击故障 |
| 异常分类及恢复状态导致故障被放大 | 检查异常转换、累计恢复预算、待办与运行状态 | 支持：具体原因曾被笼统替换；旧事件的累计 3 次不能描述为重新启动后的连续 3 次 |
| 版本校验未充分覆盖执行适配代码 | 检查运行签名文件集合 | 支持：已补齐浏览器、会话、执行循环、恢复及诊断模块 |

## 选择的修复

- 将隔离通道准备与 DOM 执行分开：初始化单独限时 12 秒，DOM 执行 5 秒。
- 按文档复用初始化结果；主文档导航后失效。页面地址或上下文变化时重新检查，不继续使用旧操作。
- 超时后最多一次隔离通道缓存重建，再有界复核；不刷新或导航、不改用主页面通道绕过身份核验、不重试发送。
- 已确认选中的目标不重复点击；选中后仍必须有身份、真实消息与唯一编辑器证据。
- 保留列表缺失、身份变化、头部未匹配、消息列表未就绪、页面读取超时、遮挡等具体故障阶段和原因。
- 显式诊断要求全部账号任务暂停，与其他诊断互斥。动作仅限原失败会话的正常选择，仍检查草稿、登录和平台校验。
- 只有唯一原失败会话真实核验通过，才解除对应事件并自动关闭恢复待办；任务仍保持暂停。
- 运行签名覆盖此次涉及的底层执行代码，防止以后只改适配器却沿用旧验收签名。

未选择更换浏览器引擎、强制点击、无限延长超时或自动清除全部异常：这些做法不能建立正确会话与安全执行之间的证据链。

## 验证与边界

覆盖冷启动、暖读取、主文档导航、通道重建次数限制、页面变化、草稿保护、暂停与接管、任务隔离、诊断无发送能力、具体错误展示以及旧异常的证据式解除。

受限诊断的独立验证窗口内，业务数据前后摘要一致（收发消息、简历、联系方式、平台申请记录）；诊断不运行回复、开聊、索简历或交换联系方式。原业务配置未改变。整个维护期间另外发生的业务执行见末尾审计补充。

Harness 的 9 项验收验证语义决策与发布约束，不代表验证真实网站按钮；真实页面与原目标会话由上述独立实机诊断验证。

不能保证 BOSS 后续永不发生导航、风控、登录失效或页面改版。本次解决的是已复现的通道生命周期问题、具体故障信息丢失，以及缺少原目标实机验证。后续不同故障必须按具体阶段记录并重新核验。

## 最终验收补充

- 完整回归：484 项通过；前台恢复与访问阻塞回归通过。
- 补齐浏览器适配文件签名后，原业务配置的 Harness 完整验收 9/9，通过后更新发布记录。
- 最终原目标复核约 2.4 秒，25 条列表可读取，真实消息与唯一编辑器均核实。
- 最终通道保护检查约 5.6 秒，随后隔离读取约 1 毫秒；原 5 秒边界确实不能等同于初始化加读取总预算。
- 原会话恢复待办已根据真实会话证据解除，任务最终保持暂停。

数据审计的范围需要明确：早先一次诊断前后业务摘要相同；整个维护期间任务曾重新启用，业务执行新增了 2 条已发送且回执核验通过的消息。因此不能将整个维护期表述为“业务数据完全没有变化”。受限诊断没有发送能力，报告为 0 条；最后暂停状态下的独立诊断前后消息、简历、联系方式和申请记录摘要一致。
