# 执行器可靠性：职责、边界与验收

## 预期与约束

LLM 产生动作建议，程序验证授权、事实、可用动作和观察版本，再由浏览器执行，最后依据真实结果确认。
可靠性要求是错误可识别、影响可约束、状态可恢复、结果可追溯，不是宣称任何网站和模型都不会失败。

- 不允许模型扩大权限或跳过暂停、时间窗口、事实校验。
- 观察、计划、配置或操作权变化后，旧决策不得执行。
- 浏览器窗口存在不代表读取正常；读取正常不代表点击成功；点击返回不代表业务完成。
- 读取可有限重试；可能产生外部效果的动作必须先核对结果，不盲目重做。
- 保留人工草稿；登录/平台校验由管理员处理；验证码不自动绕过。

## 已有能力与本轮发现的缺口

已有：动作白名单、模型输出约束、执行前重新读取状态、可用动作再校验、操作账本、防重发、平台回执核验、有限会话恢复和管理员待办。

本轮代码证据：

1. 原环境检查只打开一个含 Ready 按钮的页面并观察，没有实际定位、输入、点击和结果回读。因此原先的“浏览器检查通过”不能证明执行链路通过。
2. BOSS 读取已具备初始化与 DOM 读取分离，但通用 BrowserSession.observe 仍走另一条直接读取路径，同类故障可能重复出现。
3. 底层定位器的 timeout 不一定覆盖 SDK 的整个类人操作链。真实 CloakBrowser 的一次输入成功却耗时约 42 秒，单看结果成功无法发现执行延迟。
4. 原快速测试禁止任何 busy 实例，账号任务仅暂停但浏览器待机也无法测试；同时旧报告缺少当前浏览器实例的有效性区分。

这些是多个不同层次的问题，不能统一归因为“模型不好”或“网站风控”。元素歧义、页面变化、通道初始化、实际动作、回执必须分别核验。

## 修复

### 共享读取与有界自愈

`dom_reader.py` 为 BOSS 和通用浏览器提供同一套文档级隔离读取生命周期：初始化独立预算、文档内复用、主文档导航后失效、读取超时最多重建一次。
BOSS 仍附加域名/路径检查；不会切换主页面通道绕过身份检查。

原生动作增加外层 deadline（输入 60 秒、点击 45 秒，其他默认 45 秒）。超时保留可能的部分输入，不自动重放；具体调用方仍依据真实会话、动作账本和回执决定下一步。
计时器用于限制等待，不是硬实时保证；事件循环、驱动取消与清理可能产生额外延迟。

### 环境中的完整执行器核验

“执行环境 → 环境检查 → 快速测试”新增执行器检查，使用无网络的合成页面：

1. 读取页面结构；
2. 唯一定位输入框和按钮，并拒绝歧义目标；
3. 通过实际浏览器输入已知文本；
4. 重新观察页面；
5. 通过实际浏览器点击；
6. 回读页面真实输出，确认文本相等且点击效果恰好一次。

同一许可证容量下复用已有浏览器的新测试标签页；完成或失败后关闭测试页，恢复业务页引用及观察缓存。
此测试不向真实网站提交任何信息。功能成功但耗时偏长时保留告警，区分节奏等待、原生执行和稳定等待时间，不自动重放已成功操作。

### 任务专属核验

环境页面提供任务选择，以及：

- 检查当前页面：CDP、主页面、隔离通道、登录/平台校验和草稿保护的只读检查；
- 核验原目标会话：受限地打开原有本地绑定会话，核对身份、消息与唯一编辑器，不输入或发送。

核验结果持久保存到数据库，并绑定任务、代码签名和浏览器实例。重启后旧报告展示为历史记录，不能冒充当前实例的健康证明。

### 互斥与准入

- 全部账号任务暂停并到安全点后允许测试，不必为测试关闭整个浏览器。
- 环境检查期间不能启动账号业务任务；页面诊断与环境浏览器操作互斥，不能检查中释放浏览器席位。
- 受版本管理的 BOSS 任务启动时，除了 Harness 发布验收，还要求当前环境签名下通过执行器核验。模型验收不能替代浏览器核验。
- 报告失效或检查失败时，启动提示明确指向环境检查。真实网站的登录、会话身份与结果仍在执行时逐次校验。

## 自愈边界

| 情况 | 自动处理 | 停止边界 |
| --- | --- | --- |
| 隔离读取上下文暂时失效 | 单次重建并只读复核 | 页面变化或再次失败 |
| 元素移动、遮挡或选择失败 | 有界重读、重新定位、会话恢复 | 歧义、恢复预算耗尽、无法核验身份 |
| 模型建议对应的观察或权限已变化 | 拒绝旧动作，保留重新决策的事实依据 | 不执行过期建议 |
| 外部动作结果不确定 | 回读原系统与回执，核对已有操作记录 | 不直接重复提交 |
| 登录、平台校验、人工草稿 | 生成/展示处理提示并保留现场 | 不自动覆盖或绕过 |
| 缺少业务事实 | 待办补充后按版本重新规划 | 不补造事实 |

## 验证范围

单元测试覆盖合成页面限制、歧义拒绝、无效果/重复效果失败、原生动作超时不重放、草稿保留、模型验收不能绕过执行器准入，以及诊断互斥。

真实浏览器测试与 Docker CloakBrowser 测试分别执行合成页完整链路；后者使用现有许可证实例。
Harness 的 9 项决策验收独立运行；真实网站的页面与原目标会话单独核验。
这些测试共同覆盖不同层面，不声称证明所有未来网站动作均可靠，也不等价于抗 bot 检测测试。

产物：`runs/verification/executor-readiness-live.json` 及本轮验收记录。

## 本轮最终结果

- 491 项回归通过，执行器核验界面与窄屏布局检查通过。
- Docker 实际 CloakBrowser 的 6 项环境与执行器检查均通过，合成页面动作回读正确且点击效果恰好一次。
- 原目标会话复核约 2.7 秒通过；报告已保存并标识当前实例。
- 最终代码签名下 9/9 项 Harness 验收通过，原业务配置未改变，任务保持暂停。
- 性能提醒仍保留：原生输入约 44.9 秒，平台节奏等待为 0，稳定等待约 0.6 秒；当前证据将瓶颈定位在 SDK 原生操作范围内，尚未定位其内部具体调用，也未消除该延迟。功能通过与性能健康分别展示，不能将其包装成“全部问题已解决”。
- 对该延迟采取记录分段耗时、明确外层 deadline、超时保留现场且不重放的可靠性措施，没有通过关闭类人行为或强制点击掩盖问题。
