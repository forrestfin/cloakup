# 场景模板与双 Agent 工作区

## 问题与职责

原工作区把任务、岗位事实、草稿版本、本地候选人会话和测试流程放在同一个入口。不是聊天气泡不足，而是复用范围和数据所有权混在一起：规划一旦读取具体岗位，就难以直接复用于多个任务。

本次以“同一网站＋同一场景”的通用模板作为配置边界。本轮开放 BOSS 寻访验收；其他网站的既有任务入口保留。

| 对象 | 拥有的内容 | 不拥有的内容 |
| --- | --- | --- |
| 场景模板 | 通用目标、沟通原则、计划、提示词、通用追聊规则 | 具体岗位 JD、候选人、执行时间、额度、飞书目标 |
| 规划端对话 | 自己的历史消息、当前通用模板 | 真实岗位事实、执行端历史、候选人会话 |
| 执行端策略对话 | 自己的历史消息、当前通用模板 | 规划端历史、候选人会话 |
| 执行端模拟 | 测试事实快照、本次候选人问答、当前模板策略 | 真实浏览器、真实消息、飞书发送器 |
| 任务 | 多个岗位绑定、时间、额度、筛选、通知、已应用方案 | 模板编辑过程的即时变化 |
| 岗位 | 本地 JD、确认的脱敏事实和 FAQ | 其他岗位的事实 |

两个 Agent 的“讨论策略”修改同一通用模板，但不共享聊天历史。执行端“模拟候选人”保持独立，不会因一句模拟来信修改模板。

## 用户流程

1. 从场景模板进入规划端，用多轮对话讨论通用目标与策略；右侧“当前方案”可编辑，并在 700ms 停顿后自动保存。失败或并发冲突保留输入。
2. 执行端默认进入“模拟候选人”；编辑测试事实后开始新测试。原对话保留原事实快照。无需关联本地会话。
3. 模拟使用生产的对话语义、事实引用及动作校验，工具只返回模拟结果。每轮显示回复与判断依据。此项不等于真实网站按钮验收。
4. “应用到任务”显式选择同一网站与场景的暂停任务。全部所选任务先运行生产 Harness 固定用例，再逐一发布内部不可变配置包。应用后仍暂停。
5. 应用失败保留未应用任务原配置；跨任务发布不是数据库整体事务，意外中断时逐项展示已应用／未应用状态，绝不声称全部成功。
6. 任务的执行设置、岗位事实与管理员补充答案仍在任务页验证和应用。管理员答案不会进入通用 Agent 上下文。

模板编辑不自动扩散至任务。历史方案收进“记录”；恢复历史仅载入编辑，需重新校验和应用。

## 持久化与约束

- `scenario_template`：可编辑模板，乐观并发版本控制。
- `scenario_session`：template + agent + mode 隔离的多轮消息和 Harness 依据。
- `scenario_test_context`：新测试的默认事实；模拟会话持有事实快照。
- `scenario_version`：按策略内容哈希保存已应用的不可变方案。
- `scenario_apply`：异步校验与逐任务应用进度；重启标记中断。
- `scenario_binding`：任务最近应用的模板方案；后续任务局部覆盖不会自动反向修改模板。
- 底层继续使用任务发布包与事实摘要 CAS，新增绑定岗位也纳入事实并发保护。
- 聊天和模拟仍通过已授权的模型网关、脱敏文字处理边界。真实业务权限、工作窗口、额度、去重和回执核验继续由程序约束。

## 验证发现与修复

- 模板占位符 `{{岗位名称}}` 在 DSH system prompt 中被当作运行时变量解析，导致 0 次网关请求就失败。现在只在 Harness 传输边界将双大括号渲染为全角字面量；数据库和页面中的业务占位符保持原样。官方 SDK 集成测试验证该行为，不关闭工具／会话隔离约束。
- 页面把 `pending` 过早复位，在刷新完成前允许输入，随后可能被旧页面切换覆盖。现在刷新结束后才恢复可操作状态；鼠标按下期间不替换 DOM。浏览器回归同时检查鼠标发送与 Enter 发送。
- 新增岗位绑定必须同步扩大事实摘要的并发检查集合，避免验证后岗位事实变化未被检测。

## 验收范围

自动化测试覆盖模板抽象、CAS、双 Agent 上下文隔离、多轮模拟、事实快照、多任务应用、应用失败不改变真实配置、暂停边界、新绑定岗位事实并发保护。UI 验收拦截所有写入，真实业务写入为 0。

真实 Harness 联调使用通用讨论和虚构测试岗位事实。已有寻访任务的配置不自动替换为新模板；运行时代码升级后仅对原配置重新验证，保持业务设置不变。

## 本轮验收结果

- 全量自动化测试：503 项通过。
- 浏览器契约：双 Agent 上下文隔离、自动保存、事实快照、多轮模拟、显式应用、移动布局、任务设置归属均通过；写入均拦截。
- 真实 Harness：规划端 2 轮、执行端 3 轮通过，能依据虚构测试事实回答远程和薪酬结构。
- 原任务配置：9 项真实 Harness 隔离验收通过，重新发布原样配置；任务保持暂停，新模板尚未应用。
- 健康与会话恢复界面：回归通过。

证据位于 `runs/verification/scenario-live-acceptance.json`、`scenario-existing-task-acceptance.json` 和两张 `scenario-*-ui.png`。测试结果不代表真实网站的所有页面动作或原生输入性能已改善；此前执行器原生输入延迟告警另行保留。
