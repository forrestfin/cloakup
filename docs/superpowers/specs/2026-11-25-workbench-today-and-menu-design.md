# 工作台“今天”首页与菜单整理（2026-11-25）

## 为什么做
管理员平时很少加岗位，打开工作台主要是看“今天任务执行得怎么样”，很少点进具体对话。现状有三处让人找不到、看不懂：
1. 首页只显示任务数、启用中个数、待办条数，看不出今天开了多少聊、回了多少、有没有卡住。
2. 岗位页（`?view=sourcing`，“BOSS 岗位导入”：选岗位绑定、问候语、脱敏事实、启用自动化）不在左侧菜单里，只能从任务概览的小链接进去。
3. 同一岗位的事实在两处改：加入任务前在岗位页，加入后只能在任务“岗位与事实”页改，岗位页照样显示编辑区，保存时才报“已纳入验证后发布”。
另外，日常入口与偏调试的“场景模板／规划端／执行端”混在同一个菜单里。

## 目标
- 打开工作台的第一屏就能回答：任务在不在跑（不跑的话为什么）、今天每个岗位做了多少、有没有要我处理的事。
- 所有日常要用的页面都能从左侧菜单一步到达。
- 一个岗位的事实在任何时刻只有一个能改的地方，界面上直接指过去。

## 不做（非目标）
- 不改执行逻辑、发送规则、额度、追聊、隐私规则；不改签名文件里的执行路径（`autopilot.py`、`boss_*.py` 等）。
- 不重构 `cloakup/` 代码目录（只补一份对照文档）。
- 不做多账号、多任务的大盘；当前只有一个寻访任务，首页按“全部运行中的寻访任务”展示，有几个列几个。
- 不新增候选人对话的展示方式；对话仍在任务“候选人与结果”里看。

## 反目标（做了也算失败）
- 首页与日报共有的数字（来信、已回复、收到简历、首聊已送达）口径对不上；首聊额度与任务页、执行器口径对不上。
- 首页出现需要管理员猜的内部字样（如 `selection_blocked:editor_unavailable`、`harness_executing`）。
- 首页轮询让服务变慢或影响执行器（首页数据必须是只读、轻量的计算）。

## 选定方案：在现有结构上整理（方案一）
考虑过的另两种：
- 以岗位为中心重排菜单：任务退到幕后。改动大，要把任务详情页和岗位页拆了重拼，“事实只能一处改”的规则也要重做；现在只有 2 个岗位、管理员很少加岗位，不值得。
- 只改首页：最快，但“入口找不到”“事实两处改”仍在。
管理员选了方案一。

## 设计

### 1. 左侧菜单
```
今天            （原“工作台”，view=operations，仍是默认首页）
任务            （原“自动化任务”）
待办            （原“待办中心”，保留数量角标）
岗位            （新增，指向现有 view=sourcing，页面标题改为“岗位”）
──────────
执行环境
系统设置
▸ 高级（默认收起，记住展开状态在 localStorage，读写包 try/catch）
    场景模板 / 规划端 / 执行端
```
- 只改 `index.html` 的导航与 `app.js` 的 `contextLabels`、`parentView`：`sourcing` 的父级从 `tasks` 改为新的 `sourcing` 自身（高亮“岗位”），`chat`／`audit`／`execution` 仍归“任务”。
- 现有指向 `data-nav="sourcing"` 的小链接（任务概览里的“导入 BOSS 岗位”“设置岗位”）保留。

### 2. “今天”首页
从上到下四块，没有寻访任务时退回现有首页内容。

**a. 状态条（每个寻访任务一行）**
- 每个任务的状态用现有的逐任务口径（成员状态 + `account_execution.availability()` 的 `state`／`next_at`），映射成五种人话，不显示内部代号（实现者的决定，见文末）：

| 内部状态 | 首页显示 |
|---|---|
| 成员 running，availability `open` | 运行中 |
| availability 为时段外（`next_at` 在时段开始） | 等待执行时段（下一段 HH:MM 开始） |
| availability `resting` | 休息中（HH:MM 继续） |
| 成员 paused，最后一次 history 的 actor 为 admin | 暂停中 · 管理员 HH:MM 手动暂停 |
| 成员 paused，系统暂停 | 暂停中 · 原因（取对应待办的中文标题与说明；会自动恢复时写下次尝试时间） |
| `release_changed`／`job_not_validated`／`planning`、选择恢复 blocked | 受阻 · 原因（同对应待办，例如“版本变化，需要重新验收”） |

- 执行时段：今天的时段（例如 9:00–12:00、13:30–23:30），当前是否在时段内。
- 一个“去任务”按钮。

**b. 今日数字（按岗位一行，末行合计）**

| 列 | 口径 |
|---|---|
| 首聊 | “已用／份额”，两个数都取 `job_quota.task_quota()`（与任务概览“岗位与首聊额度”和执行器的额度口径一致：按占位计，含回执不明）；同格下方小字写“已送达 N”（今天 `intent=first_contact`、`status=sent`、`sent_at` 在当天，同日报 `first_contacts`） |
| 来信 | 今天 `observed_at` 在当天的 inbox 条数（同日报 `replies`） |
| 已回复 | 今天发出的非首聊消息（同日报 `messages_sent`） |
| 收到简历 | 今天 `resume_file_archived` 审计条数（同日报 `resumes_archived`） |
| 主动打招呼 | 今天新出现的、候选人先开口的会话数（`history[0].direction=='in'` 且首条来信在今天），括号写“未回 N”（首条来信之后没有我方消息的）。首页专有，不进日报 |
| 待回 | 此刻：最后一条是候选人来信、之后我方没有 sending／sent／回执不明消息、且不在终止状态的会话数（按岗位）。这是“现在”的数，不是日报数字，列名旁加说明“此刻” |

- 与日报共用的列（来信、已回复、收到简历、已送达）直接复用 `daily_report._outcomes` 的计算（抽成公共函数，日报输出不变）；首聊“已用／份额”与任务页、执行器同口径。日报格式本次不改，历史日报不重算。
- 日界线、时区用日报的 `day_bounds`／`report_timezone`。

**c. 需要你处理**
- 未解决待办的前 5 条（按现有待办排序），每条：标题、岗位、发生时间、一句说明，按钮“去处理”跳到待办中心并选中这条。
- 没有待办时显示“目前没有需要你处理的事”。

**d. 最近动态（最近 10 条，今天内）**
- 只列业务事件，用人话：
  - 首聊：`18:45 FDE交付工程师 · 向一位候选人发出首聊`
  - 回复：`18:47 FDE交付工程师 · 回复了一位候选人`
  - 简历：`18:47 FDE交付工程师 · 收到一份简历`
  - 候选人拒绝／转顾问：`… · 候选人表示不考虑`／`… · 转顾问接续`
  - 任务暂停／恢复、页面打不开／恢复：取自成员 history 与 `page_health` 待办
- 不写候选人姓名（统一写“一位候选人”），不链接到对话。
- 数据来源：各岗位档案的 outbox（`sent_at`）、审计（简历、拒绝、转顾问）、任务成员 history；不读日志文件。

**刷新**：沿用现有 `/api/state` 轮询，新数据作为 `state.today` 一并返回；计算只遍历当天的记录，保证在现有轮询间隔内完成。

### 3. 岗位页
- 标题“岗位”，副标题说明“绑定 BOSS 岗位、设置问候语与事实；加入任务在任务里操作”。
- 岗位列表每行新增一列“所在任务”（无／任务名）。
- 岗位已加入某个已发布的任务时（与 `job_config.save_config` 拒绝保存的判断同口径：岗位的任务有 `agent_release` 记录），岗位详情里整张配置表单（JD、问候语、沟通配置含脱敏事实与“根据 JD 生成”的草稿、回答策略里的带类型事实、常见问题、执行策略、“保存配置”按钮）改为只读展示；“启用／停用自动化”按钮和 BOSS 绑定保持可用（它们不走 `save_config`，停用某个岗位是合理的即时操作），顶部提示“这个岗位已在任务「…」中运行，事实和问候语请在任务的『岗位与事实』里修改（修改会先验收再生效）”，按钮“去修改”直接打开该任务的“岗位与事实”并选中此岗位。未加入任务的岗位保持现状可编辑。

### 4. 对照文档
新增 `docs/workbench-map.md`：菜单 → 页面 → 主要功能 → 前端函数／后端接口／Python 模块 的一张表，外加“常见操作在哪”（加岗位、改问候语、改事实、看今天、处理待办、看日报、环境检查）。CLAUDE.md 的“目录结构”加一行指向它。

## 约束
- 前端为原生 JS，沿用文件里紧凑单行写法；新增文字为中文。
- 新增后端计算放在新模块（如 `cloakup/today.py`），`workbench.state()` 只调用它；不放进签名文件的执行路径。若 `workbench.py` 本身在签名清单中，上线照常走 重建 → 草案 → 验收 → 发布 → 恢复。
- 测试：`tests/test_today.py` 覆盖各列口径（含跨日边界、首聊份额、主动打招呼与未回、无寻访任务时）、与日报同口径；前端改动以 `node --check` 与在浏览器里实看为准。
- 不改与本任务无关的代码；发现的问题单独列出。

## 实现者的决定（评审后补充，管理员可改）
- 首聊列用额度口径（已用／份额），同格附“已送达”；理由：管理员关心“额度有没有用完”，执行器也按占位算，二者不一致时以执行器为准。
- “待回”是此刻的会话数，不和日报比；日报的 `unanswered` 是全天消息数，含义不同。
- 状态映射成五种人话（见状态表），不直接显示全局 `task_state` 文字。
- 加入已发布任务后锁住整张配置表单；自动化开关与绑定保持可用。
- “主动打招呼”只在首页显示，日报本次不加列、不重算。
