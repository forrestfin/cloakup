# 沟通页卡住的自愈与自动恢复（2026-11-25）

## 现场（11-24 20:40 → 11-25 08:5x）
- 20:39:51 执行器重开沟通页后，`/web/chat/index` 一直停在 BOSS 启动页（会话 0 行、编辑器 0 个，无登录框、无验证）。
- 自愈：刷新 ×2、重开标签页 ×1 均无效 → 20:43:35 `selection_blocked:editor_unavailable`，系统暂停任务。
- 暂停后执行器只待机，12 小时无任何重试；待办却写“每 10 分钟会再自动试一次”。
- 管理员早上刷新仍卡住；从推荐牛人页点左侧菜单“消息”进入后恢复，之后刷新也正常。登录、网络、浏览器进程均正常，上线改动未触及该路径。根因（平台侧暂时状态）无法进一步确定。

## 方案（管理员已选：自愈后自动恢复）
1. **自愈多一级“从菜单进入”**（`page_health.heal`）：刷新、重开标签页都不行时，先打开另一个 BOSS 页面（沟通页 ↔ 推荐牛人页），再原生点击左侧菜单（“消息”／“推荐牛人”，可见、唯一、命中测试），等页面画好再判断；记 `healed_by='menu_entry'`。仍不行才算用尽。节奏用现有 `_act`／`jitter`，不新增绕检测手段。
2. **暂停期间定时自愈，恢复后自动继续**（`autopilot` 待机分支）：只针对“系统因页面打不开而暂停”这一种（暂停原因 `selection_blocked:editor_unavailable`，且最近一次页面检查为加载卡住／内容缺失）。执行时段内约每 10 分钟（`jitter`，有上限）跑一次完整自愈；沟通页正常、确认无未发送草稿、无登录／验证时，系统恢复任务（`actor='system'`，`reason='page_recovered'`），原会话照旧走只读复核（`resume_verification`），写 `logbook.log` 与事件。登录失效、平台验证、有草稿、管理员手动暂停，一律不自动恢复。
3. **环境检查加“BOSS 页面可用”**（`test_environment`）：沟通页、推荐牛人页各检查一次，不正常就跑上面的自愈，结果写进检查报告（不正常时说明卡在哪一步、做了什么）。
4. **待办文字按真实状态写**（`attention`）：运行中／暂停中自动自愈、下次尝试时间、已恢复即关闭；需要管理员时说明原因。同步 `daily_report.EVENT_RULES` 与测试。
5. **记录本次异常**：`docs/incidents/2026-11-24-chat-page-stuck.md`（不含候选人信息）。

## 测试（先写失败测试，名称注明“11-24 20:40 沟通页卡在启动页”）
- 刷新、重开都不行时走菜单进入并恢复；菜单不唯一或被遮挡时不点、判用尽。
- 暂停原因为页面打不开：时段内自愈成功 → 自动恢复并请求只读复核；有草稿／登录／验证／管理员手动暂停／时段外 → 不动。
- 间隔有上限且用 jitter；环境检查报告包含页面检查；待办文字随状态变化、恢复后关闭。
