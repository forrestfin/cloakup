# 规划端与执行端 Agent：版本、隔离验证与发布

## 范围与职责

本轮先覆盖 BOSS 寻访。两个入口使用同一 Harness 框架、不同逻辑会话和工具目录。规划端讨论目标、规则、事实与验收，形成草案；执行端解释生效版本与测试结果，调用隔离模拟/重放工具，提出修改草案。二者都不能从聊天直接发布、启动真实任务、发送候选人消息或调用飞书。

候选人对话是业务输入，管理员对话是控制上下文，分别持久化。两个 Agent 的会话按 task_id、agent、session_id、draft_id 绑定，不把另一个会话的管理员消息隐式拼入上下文。每个模型请求通过独立逻辑会话执行；运行进程可复用。数据库中的完整对话、每轮实际提示词、输入及上下文签名仍可查看，请求使用最近 20 条会话消息以及当前结构化草案、事实和最近测试结果；超过 30 轮需基于草案新建会话，不假称无限上下文。

## 配置生命周期

`现有配置快照 → 草案修订 → 完整隔离验收 → 暂停至安全点 → 原子发布 → 显式继续任务`

首次接入只归档现有生效配置，并标记 legacy_unverified，不把旧配置伪装成已验收。草案包含任务策略、时间窗口、岗位 JD 与脱敏事实/FAQ 快照、参考计划、规划提示词和执行端对话提示词。每次修改采用乐观锁并保存修订历史。生效事实由发布包提供，不由两个 Agent 分别维护副本。

直接保存旧任务配置、旧岗位事实或旧规划对话不能绕过发布门槛。管理员补充待办答案会先建立事实草案，再进入规划端讨论，验证发布后才可用于真实回复。待办不因草案保存或发布就被当成已答复。

发布检查草案签名、修订、测试归属、固定必需案例及真实 Harness 轨迹、基线任务版本、事实版本和执行安全点。签名包含配置包、模型标识、授权网关、Harness 版本、语义策略、验收集版本及相关执行代码摘要。修改草案或升级执行代码后必须重新验证。单次模拟或重放不能冒充完整验收。

任务配置、事实、不可变发布包、参考计划、发布指针和草案发布状态通过同一数据库事务提交；任一 CAS 失败全部回滚。发布不自动启动任务。模型或运行代码签名变化后，旧报告不能作为新启动的依据，必须重新验证发布。运行的账号任务记录采用的发布包，版本不匹配时禁止继续使用旧绑定执行。历史版本可查看和导出；恢复旧配置也应建立新草案再验证，不盲目回放历史动作。发布后仍可在原会话讨论；若提出配置修改，系统另建草案并保存会话绑定迁移历史，不改写已发布包。

## 隔离环境

测试工作器只接收配置/事实副本、测试观察副本、已授权的模型客户端和测试根目录。它不持有生产 Workbench、候选人存储对象、浏览器实例或通知发送器。测试数据库为独立 SQLite 文件，生产配置与过程仍在 PostgreSQL。Harness 文件/Shell/原生浏览器工具保持禁用。

模拟工具注册表只登记模拟实现，没有 API、浏览器或飞书真实适配器的回落路径。模型提出发送、资料申请等动作时，只写测试结果；结果中的 simulated_only 不表示真实送达。real_writes=0 指真实业务写入为零，不表示模型网络请求不存在。

测试调用真实语义 Harness、事实引用校验、动作准入和响应组装相关代码。它验证决策与工具契约，不验证真实网页按钮、登录、DOM 适配、实际简历下载或飞书送达；这些仍需真实环境健康检查和限定范围试跑。测试通过不是任意网站状态都正确的保证。

## 三种测试操作

- 自定义模拟：输入最多 12 轮文字观察、预期意图以及“已有简历/申请等待中”等状态。模型理解后通过真实动作准入，所有动作由模拟工具反馈。
- 历史观察重新决策：可选已有语义事件，使用当时已记录的脱敏观察与资料状态，套用新草案比较。没有语义事件时只能使用当前本地保存快照，并要求操作者给出预期；明确标注不是完整历史还原。不会重发历史动作，不读取现场页面。
- 完整验收：每个岗位运行固定的邀请、陌生表达、先了解、薪酬边界、指代不明、拒绝、稍后、已收简历及可用已知事实场景；所有断言和执行来源满足要求才可发布。

完整“任意浏览器工具序列的可分叉重放”不在本轮范围。重放比较意图、来源、允许动作与结果，不要求随机模型逐字生成相同回复。

## 持久化对象

- agent_bundle：不可变配置与事实快照。
- agent_release：任务生效指针及发布历史。
- agent_draft：可编辑草案、修订、基线、差异和依赖签名。
- agent_session：两类 Agent 独立多轮对话、结构化建议、隔离工具请求与结果。
- agent_test：不可篡改入口创建的测试输入、配置副本、Harness 轨迹、断言及模拟工具反馈。报告可导出。

服务重启将未完成测试标记为 interrupted，不能作为发布依据。已完成报告保留；代码和依赖签名不同则失效。候选人资料仍只在已授权自动脱敏范围内进入模型，图片和简历正文不进入测试模型。

## 本轮验收结果（2026-11-17）

- 完整回归 466 项通过。
- 最终代码上的 BOSS 固定决策验收 9/9 通过；自定义邀请模拟与原问题会话的本地历史重新决策分别通过。
- 两个 Agent 各完成两轮真实 Harness 对话，准确读取绑定的已发布版本及任务暂停状态；管理员对话输入、输出、工具结果和来源可追溯。
- 完成验证后发布，当前任务配置 v8。发布前后的已发送消息、回执、收件、联系人、简历与平台申请记录保持一致；旧决策缓存和未发送草稿按设计失效。
- 实际重启 Docker 应用后，发布包、两类会话和三类测试报告均恢复，启动前签名校验通过，任务仍暂停。
- 页面合成验收拦截所有写请求；部署后的只读页面检查无脚本错误，已发布版本仍可继续对话。

摘要：`runs/verification/platform/agent-workspaces-acceptance.json`。隔离的是被测业务状态和工具副作用；草案、测试调度及报告作为控制面元数据仍由 PostgreSQL 持久化，测试工作器使用独立 SQLite，不持有生产业务写工具。

本轮未恢复真实寻访，也未以测试方式向候选人发送消息。真实网页按钮、登录和回执仍须在任务继续后的真实执行中核验；固定决策验收不冒充端到端网站验收。
