# 候选人问题的回答逻辑

## 在哪里查看和调整

自动化任务 → 对应寻访任务 → 岗位与策略 → 回答策略。

此处显示平台规则版本、处理顺序、事实范围及问题试答。沟通配置中的可引用事实、常见问题及其相同问法可由管理员编辑并版本化保存。试答只读使用已保存配置，不联系候选人、不修改进度、不调用模型。

实际回复：候选人与结果 → 选中候选人 → 执行依据，查看“回复依据已核验”的原因、来源、事实原文和配置版本。历史记录保持原样，新增可读依据从本次更新后产生。

## 当前真实技术实现

当前不是让模型读取候选人原话并自由判断。候选人原话只在本机处理；固定意图及问题主题规则用于本地路由。模型仅接收已授权的匿名岗位事实和有限意图标签，编排受限话术。

发送、试答、管理员待办共用answering.answer_question，避免三套判断逻辑不一致。

1. 拒绝、稍后、明确的自动化身份询问等，先按对话边界处理；问候不当作岗位问题。
2. 唯一匹配管理员已启用的常见问题时，引用确认答案。
3. 检索已保存的脱敏岗位事实，按工作地点、远程安排、经验、学历、岗位要求和职责的主题寻找依据。
4. 当前规则要求每个识别到的主题有唯一明确事实；依据缺失、多条可能冲突、问题未被完整覆盖或涉及需单独确认的条件时转待办。不会把岗位发布地址直接推断成实际办公安排。
5. 不是问题的消息继续正常对话和资料收集。实际发送仍受任务暂停、身份、授权、每日上限、会话最新状态和回执保护约束。

这是有限主题的本地检索规则，尚非通用语义问答。可用管理员确认的常见问题补充问法与答案；扩大语义处理范围必须同时保留数据披露边界和可核验依据。

## 本次修复

旧逻辑将带疑问词、未精确匹配FAQ的问题直接转人工，漏查了岗位已有的“远程协作，地区不限，华中区域优先”。现优先查已确认事实，该问题直接引用上述安排。不从原始JD、模型推测或候选人自述中制造招聘方承诺。

已覆盖截图问题、问候、职业陈述、地点和薪资复合问题、出差与作息、资料缺失和冲突、已知问题不误生成待办。历史已发消息不改写或自动补发。
