# 招聘对话语义决策复盘

## 预期与约束

对于招聘对话，Harness 应理解最近几轮双方表达、当前问题、岗位事实与资料收集状态，选择回答、澄清、推进、等待或交管理员。问号不等于岗位事实问题；没有匹配到关键词不等于业务事实缺失；回复不等于无条件同意提供资料。

程序负责会话身份、任务授权、暂停、工作窗口、额度、申请去重、发送占位、事实有效版本和真实回执。未知发送不能重放。只在候选人真正询问且确实缺失事实时创建事实待办。模型错误、隐私披露阻断、页面故障需要各自独立的状态，不能伪装成需要核实岗位安排。

## 已证实的问题

1. `answering.answer_question` 使用正则判定是否问题，再按有限主题匹配事实。`not topics` 会进入 defer；因此新表达、指代、交流邀请均可能被判为事实不足。新增邀请白名单只修复部分表达。
2. `decision_runtime.capabilities` 根据上述结果裁剪 available_actions，defer 路径主要只允许 escalate。`direct_proposal` 又直接选择 answer/escalate/acknowledge_pending，使 Harness 无法纠正前置语义判断。
3. `decision_runtime.payload` 不包含多轮原话、岗位 FAQ 答案及完整结构化事实来源，只包含有限意图和概要。模型看到的是程序的结论，缺少独立判断证据。
4. `reply_step` 和 `autopilot.dispatch_reply` 负责最终固定文案。pending_ack 强制替换为“您关注的具体安排我核实清楚后再具体回复您”，甚至没有实际的待核实问题。
5. `communication_policy` 的“信息不足时说核实后回复”范围过宽；语义理解不确定、岗位事实缺失、操作结果未知被混为一类。
6. 原回归主要验证已知关键词和安全约束，未建立自然表达、同义表达、指代、多意图及多轮上下文的语义验收集。

2026-11-17 真实审计只读统计：Harness 决策 35 次，程序决策 41 次；当时记录中的 answer、escalate、acknowledge_pending 全部来自程序。统计反映该工作区当时数据，不代表所有运行的比例。

## 修复方案

采用单一 Harness 语义决策阶段，输入经授权复核或可靠脱敏的有限多轮对话、当前有效计划、带稳定 ID/版本的已确认岗位事实与 FAQ、资料及申请状态。输出结构化意图、当前问题、引用事实 ID、实际缺失项、下一动作和沟通内容计划。

关键词路由保留为检索候选和保守边界提示，不能把“无匹配”直接升级为事实缺失。模型必须先理解问题再选事实；明确拒绝、暂停等保守约束仍优先。缺事实的升级必须指出当前问题和缺失项；若只是表达不清，应澄清，不能承诺核实某个未被问到的条件。

执行前校验：事实 ID 存在、状态 confirmed、版本未变化、薪酬披露边界、动作授权、目标会话和消息指纹。回复生成失败不回落到虚构核实模板。已由语义阶段验证的回复不得被旧回答路由重新分类或覆盖。操作后真实结果进入下一轮观察。

语义状态缓存应绑定对话指纹、岗位事实/FAQ版本、策略版本；事实改变、管理员答复、新来信都使缓存失效。记录证据摘要、路由、引用事实及拒绝原因，在现有执行依据中可查看；不要记录模型私有推理链。

## 数据授权是独立前提

现有实现明确不允许候选人原话外发，采用有限词汇提取，不把任意正则替换视为可靠匿名化。不能在修复语义能力时默默扩大披露范围。已向管理员请求：允许本机自动脱敏后的最近多轮招聘对话发送到现有授权网关，或逐段复核后发送。图片、简历正文、身份和联系方式不进入模型。

授权前可以完成架构和合成验收，不把真实多轮原话发到模型。无法可靠脱敏必须转隐私复核，而非生成岗位事实缺失待办。

## 必要验证

- 原句和未列入正则白名单的同义邀请都进入正常交流。
- “外地也能做对吧”等指代从前文与远程事实取证。
- 一轮多个问题：已知部分回答，未知部分独立升级，不整句套核实。
- 收到简历后仍有问题先回答，已申请/已取得资料不重复索要。
- 拒绝、稍后、身份询问、提示注入、模型失败、事实冲突、配置变化、暂停和未知发送回执均保持原约束。
- 除替身驱动的集成回归外，使用合成脱敏案例在真实 Harness 网关运行语义验收；真实会话只在授权范围内验证。

## 本次实现

管理员已明确允许自动脱敏后的最近多轮招聘对话发送至现有火山方舟网关。授权单独持久化，不把同意推断为图片、简历正文或身份资料外发授权。

`conversation_semantics.py` 通过真实 DeepSeek Harness 增加前置语义阶段，读取最近最多 12 轮脱敏对话、已确认事实、启用 FAQ 和任务计划。关键词回答器保留为无对话授权的旧场景兼容路径；已启用语义阶段的真实来信先经语义判断，不再由旧正则决定是否缺事实。

模型选择回应片段和事实 ID，程序使用已确认事实原文及安全对话短句组合正文。这一版本优先解决“理解错问题和虚构核实事项”，没有开放任意事实改写；语言自由度仍有限，需要后续通过验收集迭代。模型校验失败允许一次反馈修正，仍不通过则保留决策待办，绝不退回通用核实模板。

语义结果持久记录在候选人执行依据中的“Harness 已理解对话与事实依据”事件，包含脱敏输入、实际提示词、语义分类、来源、回应计划及 Harness 轨迹。配置、事实、FAQ、新来信或资料状态变化使缓存失效；发送前再核验语义依据。待办中心复用同一语义结果，不独立以旧正则生成新事实缺失误报。隐私过滤失败与模型失败使用独立决策待办，不冒充缺少岗位事实。

验证：完整本地回归 450 项通过；真实官方 Harness + 现有授权网关的 12 类纯合成语义验收通过，包含原始问候、陌生邀请、指代、先了解再发简历、薪酬边界、已知与未知混合问题、缺事实、含义不清、拒绝、稍后、收到简历后提问和提示注入。该验收不发送候选人消息，不能代替上线后真实长期质量监测。

上线后只读验收：找到截图对应的本地会话，按已授权脱敏范围调用真实 Harness，输出 route=continue，计划回应“您好，可以的。您想先了解岗位的哪方面？”，missing_information=[]；未向候选人发送测试消息。部署时任务处于午休窗口，保留工作窗口，不能将该只读验收等同于候选人实际收到新回复。
