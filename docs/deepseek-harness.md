# DeepSeek Harness 接入与提示词

## 实际接入范围

任务规划通过官方 deepseek-harness-sdk / runtime-bin 0.2.2rc2 的 sdk-minimal profile 执行。不是自建同名包装器：官方原生子进程执行真实会话、输出事件，并在数据卷保留会话日志。

浏览器代理、候选人事实路由、消息授权和送达防重发仍由现有业务执行器负责。本次没有把所有自动化执行或所有模型调用改为Harness任意工具代理，也不自动更换模型提供方。

## 调用路径

任务配置与已确认匿名岗位事实 → 编译规划提示词 → 官方Harness SDK会话 → 仅监听本机的Messages桥接 → 现有已授权模型网关 → JSON Schema校验 → 任务验收目标约束 → 持久化计划及来源。

Harness只获得临时桥接凭证，真实模型密钥保留在原有Python模型客户端。框架默认文件、Shell、工作目录等模型工具被关闭，桥接层拒绝tools声明和非文本内容。Session日志上传及插件库存上传插件关闭。规划工作目录与home独立，候选人资料、浏览器cookies和原始JD不作为规划输入。

## 提示词在哪

自动化任务 → 对应任务 → 编辑目标与参数 → 规划提示词（可编辑）。

- 任务业务规划要求：可编辑，随任务配置版本保存。
- 全局沟通、隐私与输出契约：只读，业务要求不能扩大授权。
- 生成后：任务计划面板可查看实际系统提示词、当次匿名输入、提示词摘要和Harness会话ID。
- 改提示词后需重新生成计划；若要采用到显式JSON配置，载入生成结果并保存。旧计划不会追溯改写。

截图的“高端猎聘交付达人 · 寻访”和“候选人寻访与跟进”是任务名称和业务场景配置；导入时可由岗位名称拼接默认值，不是LLM规划输出。

## 验证

官方SDK进程配合本地假模型的离线集成测试，验证会话正常完成、产生事件、请求不含工具、轨迹落盘。任务提示词保存与版本变化、隐私标识拒绝、计划签名变化均有回归。线上真实模型调用需以计划记录中的harness_trace为证，不以“包已安装”代替。

官方参考：https://github.com/deepseek-ai/deepseek-harness/tree/master/python/sdk

实际部署验证：DeepSeek Harness 0.2.2rc2，经现有网关完成计划67d21579aedd41c2ae6a59ff1677da76，会话3219074aba3c40c284b1e8e1e9a93e0a，finish_reason=completed，13条原生事件，1次上游请求。232项回归及提示词编辑界面验证通过。

## 规划对话与待办反馈

任务工作空间新增“规划对话”。管理员复核的脱敏文字、历史讨论、上一版 LLM 计划和已确认岗位事实进入官方 Harness，每轮生成回复与新的计划记录；会话、请求状态、输入、版本签名、运行时回执均持久化。对话不直接修改执行策略或扩大工具权限。通用网站任务也可讨论规划，网站入口仍需探索核验。

候选人问题缺乏完整事实时，保留待答问题并生成管理员待办，不发送空泛的核实话术。待办的“补充确认答案并重规划”将原问题留在本机；管理员填写脱敏通用问法与可对外回复的确认答案。答案写入本岗位 FAQ，脱敏问答进入 Harness。关联岗位在重规划期间禁止新增动作，已有发送等待回执后才更新配置；失败持久保留，支持幂等重试。成功后由仍在运行的任务重新读取真实会话、检查人工回复及未知回执，再按 FAQ 回复。任务已暂停时保持暂停，不会被规划启动。

“答案已保存”“重规划成功”“候选人回复已送达”是三个不同状态。待办在实际相关问题解除后自动完成；内部备注不作为事实，也不触发对外发送。当前仍是规划层反馈闭环，执行层的通用自主决策循环不在本次范围内。

后续已将 Harness 接入寻访会话与首次联系决策，具体执行范围、反馈协议和确定性校验见 [持续决策执行器](decision-runtime.md)。
