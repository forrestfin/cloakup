# Harness 持续决策执行器

Harness 已覆盖 BOSS 寻访和通用网站：任务规划、探索、实施、配方 AI 子步骤与自修复均通过官方 SDK。此变化没有增加任何站点权限或候选数据披露范围。

## 循环与执行边界

1. 在真实、已绑定的会话中读取消息、附件授权与资料状态。
2. 本机构造可用动作：回答、接收简历、读取在线职业资料、索取缺失资料、等待、停止、转交顾问或生成管理员待办。动作集合取决于当前授权、已取得资料、事实路由和回执，而不是固定步骤。
3. 官方 DeepSeek Harness SDK 接收脱敏岗位事实、有限职业标签、参考计划、状态和最近工具结果，选择单个结构化动作及理由。
4. 重新读取会话，比较观察指纹、岗位/策略/候选上下文版本、计划和管理员接管状态。变化即废弃旧提议。
5. 执行网关调用现有 CloakBrowser 适配器。对外文字由已确认 FAQ、岗位事实和受限流程文案构成；不采纳模型任意生成的业务承诺。发送仍经过持久化占位和真实送达核验。
6. 将核验结果反馈给下一轮 Harness。结果未知不算成功，也不重发。每轮最多 1–4 个决策，默认 3 个，之后交还账号调度器。尚未反馈的结果持久保存，下轮继续。

Harness 原生的 shell、文件和任意浏览器工具保持禁用；它通过 JSON 提议动作，确定性的本机网关执行动作。这样模型决定业务下一步，权限和事实校验始终在模型之外。

## 隐私与事实

候选人原话、姓名、照片、年龄、性别、具体任职公司、联系方式、完整简历和页面 DOM 不进入 Harness。模型看到的是有限意图、资料是否齐备、问题是否有完整依据等状态。本机原问题匹配管理员确认的 FAQ 和岗位事实，模型仅知道本轮是否有经过校验的可用答案。

因此，本次接入不会使模型直接理解任意原始对话。当前隐私授权下无法归纳或匹配的问题仍生成管理员待办；管理员提供的脱敏问答经上一阶段的规划反馈流程进入 Harness。未开放自由文本候选资料出站。

## 保护与异常

- 已暂停、未授权、管理员接管、配置或页面变化：拒绝旧提议。
- 有待核实送达消息：只允许等待与只读回执同步，不再发送。
- 事实不足：无“回答”动作，只能等待、读可见资料或转待办。
- 候选人拒绝/稍后：不提供联系、索取资料或回复推进动作。
- 模型失败：生成决策待恢复事项，退避后重试；不退回规则自动发送。可在待办中心请求重新观察，不会启动暂停任务。
- 动作失败：反馈 blocked/not_verified 等真实结果，同一轮不重复尝试同一动作。
- 同样状态下选择等待：合并处理并退避，不持续调用模型。连续等待却仍有新来信未处理时生成决策待办，避免长期静默。
- 简历授权、实际附件、在线职业资料、实际联系方式分别记录，不相互替代。

## 平台入口

任务“目标与进度”和“运行与记录”展示持续决策记录；候选人“执行依据”保留详细观察、可用动作、选择、Harness 会话、执行结果及哈希审计。岗位“执行策略”可调整每轮最多决策步数。任务规划与多轮规划对话继续提供上下文，不能绕过执行保护。


## 通用网站执行

WebAgent 默认且强制通过 WebHarness 调用官方 SDK，不再直接调用模型工具 API。先取得 Harness 计划，每轮生成一个工具名、结构化参数、理由和证据。工具 Schema、只读探索约束、域名、敏感操作确认、页面新鲜度、任务暂停与管理员接管校验均在本机执行。结果进入下一轮，完成时验证输出 Schema 和来自已观察页面的证据片段；这不是任意业务结论的真实性证明。

截图仅在本机记录，当前 Harness 使用公开页面文字；画布等无法通过文字识别的操作交管理员。招聘站点、登录及验证码页面不进入通用文字模型。候选数据仍走专用脱敏通道。规划对话更新期间通用执行器等待，完成后切换新计划；模型调用期间出现规划或接管变化，旧提议作废。

不可确认的提交结果会记录 receipt_unknown 并停止该次运行，不自动重试。模型失败不回退到旧直接调用路径。任务“目标与进度”和“运行与记录”展示通用 Harness 轨迹，完整记录可导出。环境快速测试新增 Harness 运行时合成检查。
